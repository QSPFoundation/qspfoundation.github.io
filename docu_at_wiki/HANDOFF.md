# Handoff: конвертер Markdown в DokuWiki

## Контекст

Нужно разработать Python-инструмент, который преобразует строго выбранные исходные статьи из `docs/` в статьи DokuWiki. Все код и документация конвертера должны находиться только в `docu_at_wiki/`.
Эту ветку нельзя пушить в удалённый репозиторий.

## Что согласовано

- Исходные разделы `docs/qsp_wiki` и `docs/help_add` добавлены.
- Сопоставление исходных статей с целевыми страницами DokuWiki должно быть явным и храниться в конфигурации.
- Для конфигурации выбран TOML; целевая версия Python — 3.11 или новее.
- Изображения задаются явной картой: локальный файл связан с wiki media ID либо с отдельно подтверждённым внешним URL; загрузки изображений нет.
- По каждому исходнику хранится хэш; повторная конвертация обрабатывает только изменившиеся файлы.
- Сгенерированные статьи сохраняются в `docu_at_wiki/output/`.
- Образцы статей находятся в `wiki.qsp.org.out/`; соответствующая папка `/docu_at_wiki/wiki.qsp.org.out/` добавлена в `.gitignore`.
- `output/` и `.state/` остаются локальными и исключены из Git; публикации на wiki инструмент не выполняет.
- Источник обратной карты страниц и изображений: [urls_links_to_files.json](https://github.com/AleksVersus/qsp_wiki_to_help/blob/main/html_src/urls_links_to_files.json).
- В [`INVENTORY.md`](INVENTORY.md) сопоставлены 64 исходника с DokuWiki ID (48 из `qsp_wiki`, 16 из `help_add`); 62 включены в генерацию, две заглушки исключены, но их ID сохранены для ссылок.
- Из 9 локальных изображений 8 привязаны к wiki media ID. Для `qgen.png` подтверждён `:qgen.png`; `help_qspider/image.png` остаётся внешним изображением с исходной ссылкой.
- В [`config.toml`](config.toml) внесены 62 активные статьи, две исключённые заглушки и 9 правил изображений. TOML разобран Python 3.13; пропусков и повторяющихся целей нет.
- По решению пользователя, при удалении/исключении источника готовая статья остаётся, выводится предупреждение, из хэш-манифеста удаляется только запись источника.
- MDX-аудит: 584 fenced blocks, 8 таблиц, 359 заголовков, 398 относительных ссылок на локальные MDX и 167 внешних ссылок; локальные файлы разрешаются. Три `DOCLINK` ведут на заголовки той же статьи и преобразуются в DokuWiki-якоря по полному тексту заголовка.
- Сноски встречаются в `help_qsp.mdx` и `help_html.mdx`; `help_stat.mdx` имеет обрезанный H1 относительно front matter — не исправлять автоматически.
- Исходники и wiki-образец читаются как UTF-8. Кажущееся mojibake было особенностью чтения PowerShell без явного `-Encoding UTF8`.

## Наблюдения

- В образцах встречаются заголовки DokuWiki вида `====== ... ======`, wiki-ссылки `[[...]]` и изображения `{{namespace:file|caption}}`.

## Текущее состояние реализации

- Реализован пакет `qspdocuwiki`: TOML-конфигурация и проверки (`config.py`), Markdown/DokuWiki renderer (`markdown.py`), SHA-256 manifest и атомарная запись (`state.py`), инкрементальная обработка (`converter.py`) и CLI (`cli.py`, `__main__.py`).
- Используется `markdown-it-py` с плагином сносок; DokuWiki-разметка генерируется собственным рендерером.
- Обнаружение и явные карты страниц принимают файлы с расширениями `.md` и `.mdx`; сам рендерер работает с содержимым и не зависит от расширения.
- Команды запуска и поддерживаемые конструкции описаны в [`README.md`](README.md).
- Семь unit-тестов проходят. Все 62 активные статьи прошли `validate`; после обновления рендерера созданы 62 локальных результата. Повторный запуск пропускает все 62 страницы. `output/`, `.state/`, `.venv/` и Python-кэши игнорируются Git.
- Для skip сравниваются SHA-256 исходника, цель, версия рендерера и подпись карт страниц/изображений. При ошибке рендеринга старый файл и хэш не обновляются.
- Образцы теперь доступны в `wiki.qsp.org.out/`. Сверены примеры QSP, действий, HTML, QGen, сообщений и qSpider; рендерер обновлён по найденным различиям: `<sxh>` для fenced code, inline-код `''%%...%%''`, вложенные списки, абсолютная ссылка `:start` и размеры медиа из TOML. Текущий пример `html_classic.dokuwiki` подтверждает первоначальный стандартный рендеринг таблиц с пробелами вокруг ячеек; старый образец содержал ручные отступы.
- В Markdown-таблицах ячейки из одного символа `^` и `>` зарезервированы как маркеры объединения вверх и вправо соответственно; конвертер переводит их в DokuWiki `:::` и горизонтальный span, перенося содержимое правой ячейки в объединённую. Inline `<br>` преобразуется в DokuWiki-разрыв строки.

## Следующие шаги

1. Продолжить ручную вычитку остальных сгенерированных статей и при необходимости уточнить форматирование.
2. Принимать найденные расхождения и точечные пожелания по рендереру; перед новой генерацией запускать тесты и `validate`.
3. Эту ветку никогда не пушить в удалённый репозиторий.
