# Краткое руководство

## Как устроен конвертер

- `config.toml` — явная карта исходных Markdown/MDX-файлов, страниц DokuWiki и изображений.
- `qspdocuwiki/cli.py` — команды `validate` и `convert`; `config.py` читает и проверяет TOML.
- `markdown.py` преобразует поддерживаемый Markdown в DokuWiki, `converter.py` управляет обработкой страниц, `state.py` хранит хэши и безопасно записывает результаты.
- `tests/` содержит автоматические проверки.
- `output/` содержит локально сгенерированные `.dokuwiki`-файлы, `.state/hashes.json` — хэши исходников. Эти каталоги создаются автоматически и не предназначены для ручного редактирования.

Для работы нужны исходники в `docs/`, конфигурация `docu_at_wiki/config.toml`, код пакета и установленные зависимости. Конвертер обрабатывает файлы `.md` и `.mdx`; другие расширения для страниц не принимаются. Он не загружает изображения и не публикует статьи на wiki.

## Установка и запуск

Нужен Python 3.11 или новее. Из PowerShell перейдите в `docu_at_wiki/` и выполните:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m qspdocuwiki validate
.\.venv\Scripts\python.exe -m qspdocuwiki convert
```

Зависимости `markdown-it-py` и `mdit-py-plugins` объявлены в `pyproject.toml` и устанавливаются командой `pip install -e .`.

`validate` проверяет карту, наличие файлов и совместимость разметки, не записывая статьи. `convert` создаёт или обновляет только изменившиеся статьи. Повторный запуск без изменений должен сообщить, что страницы пропущены. Для другой конфигурации укажите `--config путь\к\config.toml` перед командой, например:

```powershell
.\.venv\Scripts\python.exe -m qspdocuwiki --config config.toml validate
```

## Ограничения исходных файлов

Конвертер обрабатывает файлы `.md` и `.mdx`, но поддерживает Markdown, а не произвольный MDX. Поддерживаются заголовки H1–H5, абзацы, списки, цитаты, inline-форматирование, ссылки, сноски, таблицы и fenced code с языками `qsp`, `text`, `html` или `js`. Front matter удаляется из результата; суффиксы якорей `{#id}` используются для внутренних ссылок.

- Сырой HTML и JSX не поддерживаются, кроме inline-тега `<br>`, который превращается в разрыв строки DokuWiki. Неиспользуемые HTML-теги и неизвестные конструкции не следует добавлять без проверки рендерера.
- Каждая локальная ссылка должна разрешаться через карту страниц. Внешние ссылки сохраняются.
- Каждое изображение должно иметь явную запись в `[images]`; не полагайтесь на автоматический поиск или загрузку файла.
- Используйте обычные Markdown pipe tables. В ячейке, содержащей только `^`, пробелы не учитываются, — это объединение вверх. Ячейка только с `>` объединяется с ячейкой справа; её содержимое переносится в объединённую ячейку. Эти символы нельзя использовать как самостоятельный текст ячейки.
- Неподдерживаемая разметка или язык кода останавливает конвертацию соответствующей страницы с ошибкой. Предыдущий результат и его хэш при этом сохраняются.

## Добавление страниц и медиа

Пути в ключах TOML задаются с `/` независимо от Windows. Ключи страниц и изображений относительны к `source_root` (сейчас `../docs`); значения `output_dir` и `state_file` относительны к папке с конфигурацией.

Чтобы добавить статью:

1. Поместите файл `.md` или `.mdx` в один из каталогов, перечисленных в `source_sections`.
2. Добавьте его путь и уникальный ID DokuWiki в уже существующую таблицу `[pages]`:

   ```toml
   "help_add/new_article.md" = "help:new_article"
   ```

3. Если исходник является заглушкой и не должен генерировать страницу, вместо этого добавьте его в `[excluded_pages]`, указав существующий для ссылок ID и причину:

   ```toml
   [excluded_pages."help_add/draft.mdx"]
   target = "help:draft"
   reason = "Черновик без содержимого."
   ```

Чтобы добавить медиа, положите файл под `docs/` и внесите его docs-relative путь в `[images]`. Для уже существующего ресурса wiki укажите точный media ID:

```toml
[images."help_add/images/example.png"]
kind = "dokuwiki"
target = "help:example.png"
width = 400
caption = "Подпись к изображению"
```

`width` и `caption` необязательны; пустой `caption` убирает подпись. Для подтверждённого внешнего изображения используйте `kind = "external"` и абсолютный HTTPS `url` вместо `target`. Убедитесь, что wiki media ID уже существует: конвертер не переносит файлы на wiki.

После изменений запустите `validate`, исправьте предупреждения и ошибки, затем `convert`. Передавая конвертеру новые страницы, включите их в `[pages]` или `[excluded_pages]`; неназначенные `.md` и `.mdx` файлы автоматически не конвертируются.
