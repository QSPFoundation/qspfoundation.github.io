# План разработки конвертера Markdown в DokuWiki

Статус: MVP реализован; формат сверен с несколькими готовыми статьями из wiki-образца.

## Цель

Создать инструмент на Python, который берёт явно перечисленные в конфигурации статьи из `docs/qsp_wiki` и `docs/help_add`, преобразует их в статьи DokuWiki и обновляет только те результаты, у которых изменился исходный файл.

Все исходники инструмента и его документация находятся в `docu_at_wiki/`. Готовые статьи сохраняются локально в `docu_at_wiki/output/`, хэш-манифест — в `docu_at_wiki/.state/hashes.json`; оба каталога исключены из Git. Инструмент не публикует статьи непосредственно на wiki. Локальные готовые статьи `wiki.qsp.org.out/` используются только как образцы и не попадают в Git.

## Зафиксированные требования

- Набор исходных статей и их соответствие страницам/пространствам имён DokuWiki задаются явной конфигурацией. Автоматически выводить карту из структуры каталогов нельзя.
- Изображения задаются явной картой: локальный файл связан с существующим ресурсом на `wiki.qsp.org` либо с отдельно подтверждённым внешним URL. Инструмент не загружает изображения.
- Карта статей и изображений хранится в TOML-конфигурации; целевая версия Python — 3.11 или новее.
- Для каждого исходного файла сохраняется хэш. При повторном запуске конвертируются только файлы с изменившимся содержимым.
- Хэш обновляется только после успешной конвертации соответствующей статьи.
- Если исходник удалён или исключён из карты, готовая статья остаётся на месте, инструмент выдаёт предупреждение и удаляет только запись об исходнике из хэш-манифеста.
- Статьи в `wiki.qsp.org.out/` служат примерами формата, оформления, ссылок и медиа-разметки, а не источником для автоматического копирования содержимого.

## План работ

1. **Инвентаризация входных данных** — первичный проход выполнен
   - Обнаружено 64 MDX-файла: 48 в `docs/qsp_wiki`, 16 в `docs/help_add`; 62 пригодны для генерации, 2 страницы-заглушки исключены.
   - Все 64 исходника сопоставлены со страницами из `urls_links_to_files.json`; ID двух исключённых страниц остаются доступны для преобразования входящих ссылок.
   - Найдено 9 локальных изображений: 8 привязаны к существующим wiki media ID, одно оставлено внешней ссылкой по решению владельца.
   - Полный список и основания приведены в [`INVENTORY.md`](INVENTORY.md).

2. **Спецификация конфигурации** — первая версия создана в [`config.toml`](config.toml)
   - В конфигурации перечислены 62 активные статьи, 2 исключённые заглушки с целевыми ID и 9 правил изображений.
   - Все 9 локальных изображений имеют явные правила: 8 wiki media ID и одно подтверждённое внешнее изображение.
   - TOML разбирается Python 3.13; все 64 исходника учтены как активные или исключённые, повторяющихся целевых страниц нет.
   - При реализации добавить проверки отсутствующих файлов, повторяющихся целей, незаданных изображений и некорректных wiki-ссылок.

3. **Базовая конвертация** — реализована в `qspdocuwiki/markdown.py` и `cli.py`
   - Markdown и MDX-файлы `.md`/`.mdx` разбираются библиотекой `markdown-it-py` с плагином сносок; DokuWiki-разметку формирует собственный рендерер.
   - Поддержаны заголовки, абзацы, списки, цитаты, inline-форматирование, inline-код, fenced blocks (`qsp`, `text`, `html`, `js`), Markdown-таблицы, сноски, Markdown-ссылки и изображения.
   - Локальные ссылки переводятся по таблице страниц, включая ID исключённых страниц; внешние URL сохраняются.
   - `DOCLINK::index::<id>` преобразуются в ссылки на заголовки той же страницы, найденные по MDX-якорям `{#id}`.
   - Front matter и Docusaurus-якоря снимаются с вывода. В Markdown-таблицах отдельная ячейка `^` означает объединение вверх, `>` — объединение вправо. Неподдерживаемая разметка останавливает обработку конкретной статьи с понятной ошибкой; прежний результат и его хэш сохраняются.

4. **Инкрементальная обработка** — реализована в `qspdocuwiki/converter.py` и `state.py`
   - SHA-256 исходника сравнивается с локальным JSON-манифестом `.state/hashes.json`.
   - Неизменившиеся статьи пропускаются; хэш обновляется после успешной атомарной записи результата. В подпись конвертации включены версия рендерера и карты страниц/изображений.
   - При удалении или исключении исходника готовая статья сохраняется, выдаётся предупреждение, из манифеста удаляется запись исходника.
   - При изменении целевой страницы создаётся/обновляется новая цель; старая статья автоматически не удаляется.

5. **Проверки и использование** — базовая проверка выполнена
   - Добавлены unit-тесты для рендеринга, объединения ячеек, ошибочного изображения и инкрементальной повторной конвертации.
   - Все 62 активные статьи прошли `validate`; пробный запуск создал 62 результата, повторный запуск пропустил все 62.
   - Команды установки и запуска описаны в [`README.md`](README.md). С образцами сверен формат статей QSP, действий, HTML, QGen, сообщений и qSpider; форматирование блоков кода, inline-кода, вложенных списков, корневых ссылок и размеров изображений скорректировано по результатам сравнения. Для таблиц использовано стандартное DokuWiki-форматирование ячеек; актуальный образец таблицы указывает, что старые примеры с ручными отступами не следует копировать.
   - Полная ручная вычитка остальных результатов и возможные дополнительные пожелания по форматированию остаются отдельным этапом.

## Предлагаемая структура каталога инструмента

Структура предварительная и может быть скорректирована при реализации:

```text
docu_at_wiki/
  PLAN.md
  HANDOFF.md
  config.toml          # явная карта статей и изображений
  output/              # сгенерированные статьи, локальные и игнорируемые Git
  .state/hashes.json   # локальный SHA-256-манифест, игнорируемый Git
  ...                  # Python-пакет, тесты и руководство
  wiki.qsp.org.out/    # локальные образцы; исключены из Git
```

## Критерии готовности первой версии

- Каждая статья явно включена в `pages` или объяснимо исключена; цели, используемые во внутренних ссылках, заданы явно.
- Ссылки на изображения формируются только по явной карте wiki media ID или подтверждённого внешнего URL.
- Первый запуск создаёт результат и манифест; повторный запуск без изменений не конвертирует статьи повторно.
- Изменение одного исходника приводит к обновлению только соответствующего результата и его хэша.
- Ошибка при конвертации не фиксирует новый хэш и не оставляет частично записанную статью.
- Неизвестная или неподдерживаемая разметка обнаруживается; статья с такой разметкой пропускается без потери предыдущего результата.
- Выходные статьи и манифест остаются локальными и не попадают в Git.
